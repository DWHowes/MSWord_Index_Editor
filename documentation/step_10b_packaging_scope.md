# Step 10b: packaging

**Scope for approval, 31 August 2026.** Repo clean at `19cf016`, suite 777
green. Measured against the working tree this morning, not recalled.

## The one thing that makes this different from the LaTeX editor's build

**This is the first time `bookindexcore` gets frozen.** The LaTeX editor's
0.3.0-alpha was built before the extraction; this application is installed as
*two editable installs*, `_editable_impl_bookindexcore.pth` and
`_editable_impl_wordindexeditor.pth`, each a shim pointing at a `src` tree
outside site-packages. PyInstaller's analyser does not follow a `.pth` shim the
way an import does.

So whatever this step learns is **not this application's**: `ToA_Builder` and
the InDesign editor will meet it, and it belongs in the host-developer
document's §9 when it is known. That is the deliverable people will forget.

## What is already right, and why

Worth stating because it means this is a build rather than a repair:

- **`app_paths.py` is frozen-aware and was written for this step.** Its own
  docstring says so: *"Step 10 is packaging, which is exactly when this would
  otherwise bite."* The LaTeX editor shipped an installer whose entire Help
  system would have been silently absent, and that lesson was applied here
  before there was anything to package.
- **The venv is `PySide6-Essentials` only** (6.11.2), no Addons. The LaTeX
  editor's 635MB → 201MB measurement was applied here from the start.
- **No dynamic imports** anywhere in the core or the application: no
  `import_module`, no `__import__`. Static analysis can see everything.
- **The WdX mark exists**, `icons/wdx.ico` plus the six PNG tiles, generated by
  the core's `branding/make_marks.py`.
- Help (15 topics) and icons live **inside the package**, which is what
  `app_paths` resolves against.

## What is missing

There is no `.spec`, no `installer/`, no `PACKAGING.md`, and **PyInstaller is
not installed in the venv**. All four are this step.

## A trap that is already in the code

`wordindex/__init__.py` reads its version from installed metadata:

```python
__version__ = _version("wordindexeditor")   # falls back to "0.0.0+source"
```

**A frozen build has no `.dist-info` unless one is bundled**, so the About box
would report `0.0.0+source` to a tester being asked which version they are
running. The LaTeX editor avoided this by keeping a literal in
`app_version.py`; this application chose metadata, which is better
engineering and needs `copy_metadata` in the spec to survive freezing. **To be
verified in the built binary, not assumed either way.**

The same file is what the installer's `MyAppVersion` has to agree with. The
LaTeX editor pins the two with a test; this has no equivalent yet.

## The work

1. **`requirements.txt`** and PyInstaller into the venv.
2. **`WordIndexEditor.spec`**, onedir. Named risks, each from the LaTeX build:
   `contents_directory='.'` on `EXE(...)` and **not** `COLLECT(...)`;
   `pathex` covering both `src` trees for the editable installs;
   `datas` for `help/`, `icons/` and the metadata; `excludes` for anything the
   venv carries that the app does not import.
3. **`installer/WordIndexEditor.iss`**, per-user (`PrivilegesRequired=lowest`,
   `{autopf}` under `%LOCALAPPDATA%\Programs`), `SetupIconFile` on `wdx.ico`,
   `[UninstallDelete]` for any runtime state, and a Start Menu entry.
4. **A test pinning the installer's version to the module's**, the way
   `test_about_dialog.py` does in the LaTeX repo.
5. **`PACKAGING.md`**, written from the build that actually runs, not from
   this scope. It replaces this file as the record.
6. **The host-developer document gains what freezing a shared package needs**
   (§9), which is the part that outlives this application.

## Verification, which is the half that finds things

The LaTeX editor's rule: *verified end to end, not "it compiled"*. So, in
PowerShell rather than bash, because Git Bash mangles Windows installer flags
and cost real debugging time there:

silent install to a chosen directory → launch from the installed location →
**open a real manuscript** → **press F1**, because Help is the thing that
silently disappears → check the About box reports a real version → confirm the
icon is in the exe → silent uninstall → directory gone.

**Delete runtime state from `dist/` before running ISCC.** The LaTeX build
shipped a `session_logs/` folder into its installer by doing exactly that.

## Decisions

1. **Version for the first build.** Recommend **0.1.0-alpha**, matching how the
   LaTeX editor numbered its first packaged alpha. `pyproject.toml` currently
   says `0.0.1.dev0`, which is a development marker rather than a release.
2. **Ship documentation with it?** The User Guide here is Markdown with PNG
   figures and there is **no PDF**, unlike the LaTeX editor's three. The whole
   guide is already inside the app under F1. Recommend **shipping no separate
   documentation** for this build and revisiting if a PDF is ever exported.
3. **Publish a release?** This repository is **private**, and the LaTeX editor's
   was made public specifically so alpha testers could download without a
   login. Recommend **building and verifying the installer only**, and leaving
   publication as your call: making a repository public is not a step to take
   on a recommendation.

## Out of scope

Code signing, the SmartScreen warning, auto-update, and any change to what the
application does. Also the Norton `IDP.Generic` heuristic, which flags
PyInstaller output and is recorded already; if it fires, it is a note in
`PACKAGING.md` and not a change to the build.
